# 生意参谋数据工作台

把自己有权使用的生意参谋导出报表，整理成可追溯的经营分析和行动记录。

**这是可运行的半成品 / 参考框架，不是完整商业产品，也不是阿里巴巴官方工具。** 本仓库从原有 v1.1.0 分享包整理，不能与后续的万相台推广工作台混为一谈。

## 已有能力与边界

- 经营总览：读取首页导出 ZIP，按日期查看指标、趋势、周期对比和数据来源。
- 交易、流量、客户专题：使用已适配的导出表结构分析；不是任意 Excel 自动适配。
- 数据审计、经营诊断、行动管理、系统状态。
- 其他模块目前主要提供数据归档入口，不代表商品、关键词、市场等诊断已完整实现。
- 无真实数据、无平台登录、无自动爬取、无内置 AI 服务。导出文件格式变动时需重新核对字段映射。
- 多店铺请用独立项目副本与独立端口，当前版不提供完整多租户隔离。

## 本地启动

## 如何下载并交给 WorkBuddy

1. 打开 https://github.com/dstmg/sycm-data-workbench 。
2. 点击绿色 **Code** 按钮，选择 **Download ZIP**。
3. 将 ZIP 解压到一个独立目录，避免与其他店铺或已有项目混在一起。
4. 在 WorkBuddy 中打开解压后的项目文件夹，复制 `WORKBUDDY.md` 中的提示词。
5. 让 WorkBuddy 先检查运行环境、安装依赖、运行空数据测试，再启动页面。暂时没有报表也可以先启动。

熟悉 Git 的用户也可运行 `git clone https://github.com/dstmg/sycm-data-workbench.git`。

## 运行环境与启动

需要 Node.js 20 或更高版本、Python 3.10 或更高版本，且 `node`、`npm`、`python` 在 PATH 中。Python 解析脚本使用标准库，无需安装 pandas/openpyxl。

在项目根目录运行：

```sh
npm ci
npm start
```

打开 http://127.0.0.1:5177 。首次无数据时显示等待导入，不会预置或生成虚构业绩。

更换端口（PowerShell）：

```powershell
$env:PORT = '5178'
npm start
```

配置示例见 `config/shop.example.json`。需要配置时复制为 `config/shop.json`；后者被 Git 忽略，店铺配置不应上传。

## 数据如何放入

启动或运行 `npm run audit` 后会创建 raw 分类目录。保留平台原始 ZIP，不要直接改写文件内的表头和列顺序。

| 目录 | 数据 |
| --- | --- |
| raw/01-首页 | 首页 / 经营概况导出 ZIP |
| raw/02-交易 | 交易模块导出 ZIP |
| raw/03-流量 | 流量模块导出 ZIP |
| raw/04-客户 | 客户模块导出 ZIP |
| raw/05-商品 至 raw/10-业务专区 | 其他模块的归档入口，部分尚未实现解析 |

当前自动构建逻辑主要消费 ZIP 中的 XLSX。目录审计能看到 XLSX/CSV 等，不等于这些格式都可直接分析。其他用户的导出方式、字段位置、会员版本可能不同：先审计、对账，再解读。

查看路径：经营总览 → 数据审计 → 交易/流量/客户 → 经营诊断 → 行动管理。没有数据或证据时不要把规则输出当作事实原因。

## 隐私与安全

- 只监听 `127.0.0.1`，仅供本机使用。不要部署到公网或用隧道公开；没有完整鉴权体系。
- `raw`、`audit`、`evidence`、`normalized`、`reports`、`action_exports` 与店铺配置均为本地私有文件，被 Git 忽略。
- 已从分享包中剔除历史截图、原店铺标识与机器路径说明。
- 使用 WorkBuddy 时，AI 读取文件不等于完全离线。请了解其数据处理规则，必要时先脱敏；不要提供 Cookie、密码、密钥或客户个人信息。
- 经营数据、人数、率值不应跨周期无条件相加；没有成本和毛利不能从 GMV 直接推断利润。
- 不要把原始报表、诊断结果或截图放到公开 Issue。

## 验证

```sh
npm run test:empty
```

此测试检查无数据首次启动的页面、等待状态、模块接口和本机监听。原 `npm test` 是特定私有数据集的回归脚本，不适用于空仓库，保留为 `npm run test:dataset`，需自行准备兼容数据后调整断言。
